## Finding your way around

This is a five-person repository. Before reading files at random, ask the knowledge graph:

```
graphify query "how does a field name in pack.yaml reach the corpus register"
graphify explain "PackManifest"
```

See `docs/GRAPHIFY.md`. If `graphify` is not installed, `docs/field-dictionary.md` and
`core/contracts.py` are the two files that explain most of the system.

## The three things agents get wrong here

1. **Editing a generated file.** `core/document_schemas.py`,
   `corpus/register/core_columns.csv`, `corpus/register/batch.template.csv` and
   `docs/field-dictionary.md` are generated by `python -m packs.build` from
   `core/documents.yaml`; `team/*/tasks.md` is generated by `python scripts/build_team_tasks.py`
   from `docs/team-tasks.csv`. Change the source and regenerate. A field name — and a
   task — is written down in exactly one place in this repository.
2. **Widening a contract to make a feature easier.** `core/contracts.py` and
   `db/migrations/` are separate, reviewed pull requests. If your task needs a change
   there, stop and say so.
3. **Working outside your lane.** Ownership is by directory and enforced by
   `.github/CODEOWNERS`. Staying inside it is what lets five people and their agents
   work on one repository at once.

## Before you say you are done

```
make check
```

That runs the generated-files-in-sync gate, ruff, mypy and pytest. If it fails, it is not
done.
